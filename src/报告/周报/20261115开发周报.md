# 20261115 开发周报：RT24 核心启动方法与固件实现

## 一、RT24 核心启动方法的确定

### 1. 目标

让 SPACEMIT K3 上的 RT24 实时核运行自定义固件，并能观察到 RT24 侧的输出。

### 2. 验证性测试

在移植 RME 之前，先用 ostool 做了一次验证性测试。测试的目的不是形成最终方案，
而是确认 RT24 核心的启动方法与必要步骤，因此采用最短路径实现：

- ostool 只负责把 **AP 固件**下载到板子并启动；
- RT24 固件的拷贝、启动和日志转发全部由 **AP 固件**完成。

三个固件依次接力：

```text
ostool → ap.elf → rt24m.bin → rt24s.bin
```

AP 固件运行在 S 态；M 态固件负责握手、PMP 配置和进入 S 态；S 态固件自行构造
Sv39 页表，打开 `satp` 后在高半区执行。

### 3. 测试确认的启动步骤

| 步骤 | 要求 | 原因 |
|---|---|---|
| 加载与启动分离 | 镜像拷贝期间保持复位与休眠 | 镜像未就位时核已开始取指会跑飞 |
| 拷贝后回写 cache | 拷贝完成即执行 cache 写回 | 否则 RT24 可能读到陈旧或半截代码 |
| RCPU 寄存器写入顺序 | 先释放 APMU 复位并等时钟稳定，再置执行允许，最后解除复位并唤醒 | 寄存器顺序不当会导致核停在异常状态 |
| 握手方式 | RT24 启动后改写自己的 boot entry，AP 轮询该值 | 轮询前需失效该地址所在 cache 行 |
| PMP 配置 | M 态先放行 S/U 态访存 | RISC-V 规定 PMP 无命中时 S/U 态访存失败 |
| 页表存放位置 | 页表在共享 SRAM 中构造后再开启 Sv39 | 页表 walker 读不到尚未回写的页表项 |
| 日志通道 | 输出经共享内存日志环，由 AP 转发到 UART | AP 是唯一操作 UART 的核，避免多核竞争 |

### 4. 结论

RT24 核心的启动方法确定为：**ostool 只需启动 AP 固件；AP 固件负责把 M 态与
S 态镜像加载到 RT24 私有 DDR，按序写入 RCPU 寄存器，唤醒 RT24 并与之握手，
同时承担日志转发。**

本周据此把该启动方法工程化：S 态固件替换为 RME 内核，并为其补充 RT24 的板级
配置；AP loader 与 M 态固件各自独立成仓库，启动链路按职责拆分。

## 二、本周概览

本周的工作分布在四个仓库：RME 内核（`M7M01_Eukaron`）、用户态 init 程序
（`M7M03_Anomalocaris`），以及新建的 AP loader（`M7M04_RT24Loader`）与 M 态
固件（`M7M05_RT24M`）。主线是给 RME 内核增加 SPACEMIT K3 的 RT24 实时核板级
配置，并实现 RT24 上的启动链路。

三部分的分工：RME 内核提供可在 RT24 上运行的 S 态内核；AP loader 负责将 M 态
固件与 S 态内核送入 RT24 私有 DDR，并转发 RT24 的输出；M 态固件负责 RT24 的
早期启动、PMP 配置与 SBI 服务。

## 三、主要工作

### 1. RT24 板级配置

新增 SPACEMIT-K3-RT24 平台支持：独立的板级头文件
`Include/Platform/RV64V/Chip/SPACEMIT-K3-RT24/rme_platform_spacemit_k3_rt24.h`
和独立的项目目录 `Project/GCC-SPACEMIT-K3-RT24/`，其中包含链接脚本
`rme_platform_spacemit_k3_rt24.ld`、Makefile、`ostool-build.toml`、
`ostool-board.toml`、运行脚本 `run_rt24.sh`，以及 ostool 要求存在的
`Cargo.toml` 与 `src/lib.rs`。

#### 地址布局

RT24 的物理内存与 AP 侧不重叠，板级配置按下面的方式安排：

| 用途 | 物理地址 | 虚拟地址 |
|---|---|---|
| M 态固件（RT24M） | `0x100200000` | — |
| S 态内核（RME） | `0x110000000` | 高半区 `VA = PA + 0xFFFFFFC000000000` |
| init 镜像 | `0x110400000` | — |
| KOM（内核对象） | `0x111000000` | `0xFFFFFFC111000000` |
| init 用户程序入口 | — | `0x20000000`（与 X64 端口一致） |

整个工作集（内核镜像、init 镜像、KOM、每 CPU 栈）落在一个 1GB 映射窗口
`[0x100000000, 0x140000000)` 内，页表只放两个 1GB 大页叶子：identity 与高半区。
内核 `.bss`（KOT 位图与每 CPU 的内核栈、用户栈）安排在 init 镜像下方，init
镜像被内嵌进内核镜像；每 CPU 的用户栈是 64KB，映射在 `0x20200000` 以下。

#### 内核端口的适配

- **单核启动**：`RME_RV64V_CPU_NUM` 设为 1，RT24 core0 是唯一被启动的核；
- **boot 根表位置**：改到共享 SRAM `0xC0802000` 构造（日志环在 `0xC0801000`，
  两者不重叠），根表由内核在运行时构造，固件不提供页表；
- **开页表的顺序**：发布 PTE 之后补一次 `fence` 再写 `satp` 并执行
  `sfence.vma`——`sfence.vma` 不是内存屏障，直接写完 PTE 就开页表会读到尚未
  回写的页表项；
- **trap 入口安装时机**：`stvec` 在 `tp`/`sscratch` 初始化完成之后才装载；
- **Zicbom 可选**：没有 Zicbom 时，cache 维护 KFN 直接返回失败，而不是执行
  可选指令或假装成功。

### 2. AP loader（新建）

AP 侧固件，负责将 RT24 上的固件加载并启动，同时把 RT24 的输出带回串口。

#### 代码结构

| 文件 | 作用 |
|---|---|
| `Source/rme_image.s` | 用 `.incbin` 把 M 态固件和 S 态内核镜像内嵌进 loader |
| `Source/rme_loader.c` | 主体流程与日志转发 |
| `Source/rme_loader_gcc.s` | cache 维护（flush / inval） |
| `rme_loader.ld` | 链接脚本 |

#### 启动流程

1. 检查内嵌镜像非空且大小合法，避免把空镜像拷进 RT24；
2. 释放 APMU 复位并等时钟稳定，再释放系统复位；
3. 置执行允许，同时保持 core0 处于复位与休眠；
4. 清空共享日志环，避免 RT24 侧写入时带上旧数据；
5. 把 M 态固件与 S 态内核分别拷到 RT24 私有 DDR，拷完做 cache 写回；
6. 写 boot entry（64 位地址，LO/HI 都要写）与 hartid；
7. 解除复位并唤醒 core0；
8. 轮询 boot entry 完成握手：固件启动后把自己的 boot entry 改写为 1，轮询前
   失效该地址所在 cache 行。

涉及的 RCPU 寄存器：

| 寄存器 | 地址 | 作用 |
|---|---|---|
| `PMU_AUDIO_CLK_CTRL` | `0xd428294c` | 解除 APMU 复位、等时钟稳定、释放系统复位 |
| `RCPU_EXECUTION_CTRL` | `0xc088c030` | 置 1，允许 RT24 执行 |
| `RCPU_CORE0_BOOT_ENTRY_LO/HI` | `0xc088007c` / `0xc0880080` | 启动入口 |
| `RCPU_CORE0_HART_ID_SET` | `0xc0880084` | 写 hartid |
| `RT24_CORE0_SW_RESET_REG` | `0xc088c0cc` | 0 保持复位，1 解除复位 |
| `RT24_CORE0_SW_WAKEUP_REG` | `0xc088c0d4` | 0 保持休眠，1 唤醒 |

#### 日志转发

RT24 侧不直接写串口，输出写进片上 SRAM 的日志环，由 AP 轮询后转发到 UART0，
AP 是唯一操作串口的核。

### 3. M 态固件（新建）

运行在 RT24 上的 M 态固件，负责早期启动并提供最小 M 态环境。

#### 启动契约

`Include/rme_rt24.h` 是 AP、M 态固件和链接脚本共用的契约，约定 M/S 态物理地址
与限长、日志环地址与大小、MTIME/MTIMECMP 地址以及全部 RCPU 寄存器地址。日志环
是单生产者单消费者结构，head 与 tail 各自独占 cache 行（64 字节对齐），避免
两个索引落在同一条 cache 线上互相污染。

#### 固件职责

- **握手**：启动后把自己的 boot entry 改写成 1，通知 AP 已经运行；
- **PMP**：配两个 TOR 区域，覆盖共享 SRAM 与 RME 私有 DDR，并把 M 态固件自身
  排除在外；写完回读 `pmpcfg0` 与 `pmpaddr3` 校验；
- **trap 处理**：处理 ecall 与异常；U 态的 ecall 和缺页委派给 RME，S 态 ecall
  保留在本核处理。CVA6 读不到 time CSR 时，用全局 mtime 模拟 `rdtime`；
- **最小 SBI**：实现定时器设置与调试串口输出，按 SBI 0.2 的约定返回错误码；
- **进入 S 态**：清 `satp`、配置 `mcounteren`/`mscratch`，`mret` 到 S 态入口。

### 4. ASID 分配的调整

把 ASID 的分配从内核内部移到调用方：

- 内核侧不再维护全局分配器，改为提供 `satp` ASID 字段的打包/解包宏，切换
  页表时按 ASID 失效对应的 TLB 表项；
- 内核给 init 地址空间分配最小的一个 ASID；
- 用户态基准自带 bump 分配器，从内核给出的 ASID 之后开始取号（基准从 2 开始，
  因为 1 已经分给 init）。

### 5. 基准测试与代码整理

- 清掉基准对象分配里的魔数，删除无用测试（单次提交删掉约 1700 行），IDLE_SLEEP
  同时用 time CSR 计时；
- init 程序改用 RME 的命名风格，`benchmark.rs`/`syscall.rs` 改为
  `rme_benchmark.rs`/`rme_syscall.rs`，函数与常量统一加 `RME_` 前缀；
- 修复并优化 INV 基准：嵌套调用的桩函数改用普通返回恢复 `s0-s11`，去掉嵌套
  错误标志，未使用的槽位明确标注；
- 整理 RV64V 端口的宏、声明与注释。
